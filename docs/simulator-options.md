# Simulator options

This comparison is based on official documentation and does not install or download a simulator.

| Option | What it is | Setup effort for this team | Can it simulate LiDAR? | Can it reuse Purdue LiDAR-Forest data? |
|---|---|---|---|---|
| Gazebo with ROS 2 | A robotics simulator with worlds, robot models, sensors, and ROS 2 integration. [Gazebo docs](https://gazebosim.org/docs/latest/ros_installation/) [ROS 2 Gazebo tutorial](https://docs.ros.org/en/jazzy/Tutorials/Advanced/Simulators/Gazebo.html) | Medium to high: the team must learn ROS 2, build a world, add a rover, and connect sensor topics. | Yes. Gazebo provides lidar sensor systems and ROS 2 bridges. [Gazebo sensors](https://gazebosim.org/docs/latest/sensors/) | Partly. The simulated point records can be replayed or used as expected-output fixtures, but the sources do not state a direct import path into Gazebo. |
| NVIDIA Isaac Sim | A physics and robotics simulator with configurable sensors and ROS 2 integration. [Isaac Sim documentation](https://docs.isaacsim.omniverse.nvidia.com/latest/ros2_tutorials/index.html) [RTX lidar](https://docs.isaacsim.omniverse.nvidia.com/latest/sensors/isaacsim_sensors_rtx_based_lidar.html) | High: it adds a large simulator stack and hardware/GPU setup risk for a three-month student project. | Yes, including RTX LiDAR sensors. [RTX lidar](https://docs.isaacsim.omniverse.nvidia.com/latest/sensors/isaacsim_sensors_rtx_based_lidar.html) | Partly. Purdue point records could be used for comparison or replay, but a direct import workflow is NOT STATED IN SOURCES. |
| Python plus Open3D | A small custom simulator built from point-cloud files, simple rover motion, and collision checks. [Open3D point-cloud documentation](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html) | Low to medium: less infrastructure, but the team must implement motion, sensor sampling, obstacles, and repeated-run evaluation. | Partly. Open3D processes point clouds; a realistic LiDAR sensor model must be implemented by the team. [Open3D point-cloud documentation](https://www.open3d.org/docs/release/tutorial/geometry/pointcloud.html) | Yes for replay/fixtures: LiDAR-Forest's documented x, y, z and semantic/instance records can be loaded by a custom Python pipeline. A ready-made adapter is NOT STATED IN SOURCES. [LiDAR-Forest paper](https://arxiv.org/html/2402.04546v2) |

## Recommendation

Use Python plus Open3D first. It has the smallest setup burden and is enough for measurable repeated navigation runs, collision counts, and forest point-cloud processing. Keep Gazebo with ROS 2 as a stretch option if the team needs realistic ROS topic integration. Do not make Isaac Sim a dependency for this three-month project unless the team already has the required GPU setup and experience.
